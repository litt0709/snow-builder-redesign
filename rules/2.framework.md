# Khung Thực Thi AI-DD (Framework)

> Định nghĩa phương pháp phát triển phần mềm lấy AI làm trung tâm (**AI-Driven Development**) áp dụng thống nhất cho SNOW Builder và Speedy DevKit.

---

## 1. Mô hình Tư duy (Mental Model)

**Chu trình cốt lõi của mọi Stage chuyên môn (chế độ mặc định `strict`):**
`Nạp Context Packet` → `Thực thi trong Scope` → `Ghi Artifact` → `CLI Validate Contract & Cập nhật State` → `Hiển thị Link & Tóm tắt` → `Human Gate (Approve / Request Changes / Abort)`

- **Workflow deterministic** quyết định thứ tự stage, ngân sách, điều kiện dừng và gate.
- **LLM** chỉ giải quyết bài toán chuyên môn bên trong phạm vi UoW đã được duyệt, không được tự ý sửa lại policy hay tự duyệt gate.

---

## 2. Năm Luồng Thực thi Chuẩn (Adaptive Routing)

| Flow Mode | Khi nào kích hoạt | Chuỗi Stage |
|---|---|---|
| `setup` | Dự án ứng dụng chưa khởi tạo baseline knowledge | Kiểm tra môi trường → Scan codebase → Cấu hình → Sinh baseline docs & rules |
| `feature` | Thêm mới hoặc thay đổi hành vi/kiến trúc | Bootstrap → Analyst → Architect → Implementer → Reviewer → Tester → Docs → Wrap-up |
| `fix` | Sửa lỗi / regression | Bootstrap → Pre-flight & Tái hiện lỗi (Root Cause) → Analyst → Architect → Implementer → Reviewer → Tester → Docs → Wrap-up |
| `simple` | Thay đổi nhỏ (1 file docs/config an toàn, không đổi logic/API/DB/auth) | Bootstrap → Duyệt Scope → Implementer → Kiểm tra phù hợp → Wrap-up |
| `verify` | Kiểm chứng độc lập mã nguồn đã có (không sửa code) | Bootstrap → Xác nhận Scope & Yêu cầu → Reviewer → Tester (tùy chọn) → Verify Report → Wrap-up |

> **Quy tắc định tuyến theo rủi ro**: Thay đổi dù chỉ 1 file nhưng chạm tới xác thực (`auth`), phân quyền, thanh toán (`payment`), migration/schema, hoặc cấu hình bảo mật **không bao giờ** được xếp vào `simple`.

## 3. Quản lý State & Resume Bền vững

Mọi phiên làm việc được định danh bằng `sid` không đụng độ (`YYYY-MM-DD-<slug>-<6hex>`):

```text
sessions/<sid>/
├── state.json                 # Nguồn state canonical duy nhất (atomic + CAS revision)
├── state.md                   # Bản hiển thị Markdown sinh tự động từ state.json
├── handoff-1-analyst.md       # Implementation Brief & AC list
├── handoff-2-architect.md     # Architecture Brief & ADR
├── handoff-3-implementer.md   # Tóm tắt code changes & kết quả kiểm tra sơ bộ
├── handoff-4-reviewer.md      # Verdict độc lập & danh sách issue kèm evidence
├── handoff-5-tester.md        # Ma trận AC → Test → Kết quả thực thi
└── handoff-6-docs.md          # Đồng bộ tài liệu & changelog
```

- **Trạng thái Stage**: `pending → running → awaiting_approval → approved` (các nhánh dừng: `failed`, `blocked`, `aborted`).
- **Resume an toàn**: Khi tiếp tục trên phiên chat mới, CLI đối chiếu `state.json`, checksum của các artifact đã duyệt và snapshot code hiện tại. Stage đã `approved` với input không đổi sẽ được giữ nguyên, không chạy lại tốn token.
