# Khung Thực Thi AI-DD (AI-Driven Development Framework)

> Định nghĩa phương pháp phát triển phần mềm lấy AI làm trung tâm (AI-DD) được hiện thực hóa bởi lõi deterministic CLI của Speedy DevKit.

---

## 1. Nguyên Lý Cốt Lõi (Mental Model)

**Chu trình lặp có kiểm soát**:
`AI Phân tích & Lập Plan` → `Căn chỉnh (khi có câu hỏi mở / rủi ro cao)` → `Thiết kế & Chia UoW` → `AI Implement` → `Review Độc Lập & Verify Thực Tế`

**Ba pha chính (Phân kỳ Context — Adaptive Depth)**:
1. **Inception (What & Why)**: Nhận diện dự án (greenfield/brownfield) → Khảo sát codebase (nếu brownfield) → Phân tích yêu cầu (Functional & Non-functional) → Khóa `AC-001..N` & Scope → Thiết kế giải pháp (`ADR`) & chia Units of Work (UoW).
2. **Construction (How)**: Thực thi theo từng UoW: Thiết kế chi tiết logic & NFR (bảo mật, hiệu năng) → Sinh mã nguồn sạch đúng chuẩn → Review độc lập → Kiểm thử Unit / Integration / Build / E2E.
3. **Operation & Kaizen**: Đồng bộ tài liệu dự án, kiểm chứng sẵn sàng bàn giao, ghi nhận Audit 4 lớp trung thực và đúc kết bài học kinh nghiệm (Lessons Learned).

---

## 2. Năm Chế Độ Định Tuyến (`Flow Mode`)

| Mode | Điều kiện áp dụng | Chuỗi thực thi |
|---|---|---|
| `setup` | Dự án đã có code nhưng chưa khởi tạo `ai-workspace/state/setup.json` | Kiểm tra môi trường → Scan → Sinh tài liệu nền, rules & style |
| `feature` | Tính năng mới hoặc thay đổi hành vi/interface/kiến trúc | Bootstrap → Analyst → Architect → Implementer → Reviewer → Tester → Docs → Wrap-up |
| `fix` | Sửa lỗi / regression | Bootstrap → Root Cause Pre-flight → Analyst → Architect → Implementer → Reviewer → Tester → Docs → Wrap-up |
| `simple` | Chỉnh sửa nhỏ 1 file cấu hình/văn bản an toàn, không đổi logic/API/schema/auth | Bootstrap → Implementer → Kiểm tra phù hợp → Wrap-up |
| `verify` | Kiểm tra mã nguồn đã có so với yêu cầu (không sửa code) | Bootstrap → Reviewer → Tester (tùy chọn) → Verify Report → Wrap-up |

---

## 3. Cơ Chế Kiểm Soát Rủi Ro & Chế Độ Gate (`balanced` vs `strict`)

1. **Smart Stage Gate (`balanced` — Mặc định)**:
   - Sau mỗi stage chuyên môn, chạy 1 lệnh `python3 -B .speedy/scripts/speedy_cli.py state complete --sid <sid> --stage <stage>`.
   - Các stage rủi ro thấp đạt đủ Handoff Contract và không có câu hỏi mở sẽ **tự động đi tiếp** để tối ưu tốc độ và token.
   - **Bắt buộc dừng hiện HITL (`ask_question`)** khi xảy ra bất kỳ điều kiện nào sau đây:
     - Handoff có mục `## Open questions` thực sự cần người dùng chốt;
     - Task thuộc vùng rủi ro cao (`high_risk`: `auth`, `security`, `payment`, `schema`, `migration`, `breaking`, `concurrency`...);
     - Reviewer trả `Verdict: REQUEST_CHANGES` hoặc chạm trần retry (`blocked`);
     - Xung đột file khi cài/update hoặc thao tác phá hủy (`git push`, release, xóa dữ liệu).
2. **Strict Stage Gate (`--policy strict` hoặc `SPEEDY_GATE_POLICY=strict`)**:
   - Dừng chờ người dùng chọn `Approve / Request Changes / Abort` sau mỗi stage chuyên môn.
3. **Pre-Review & Independent Verification**:
   - Tách bước tự kiểm tra cú pháp/test cục bộ của Implementer khỏi bước đánh giá độc lập của Reviewer và Verification Gate (`verify run`) có chống Test Laundering.
4. **Session Isolation**:
   - Mỗi phiên làm việc được cô lập hoàn toàn tại `ai-workspace/sessions/<sid>/` (`state.json`, `state.md`, `handoff-*.md`, `evidence/`), hỗ trợ pause/resume và selective invalidation an toàn.
